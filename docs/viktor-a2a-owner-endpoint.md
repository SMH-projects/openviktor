# Viktor A2A owner endpoint (candidate, 08.10.2026)

This candidate adds a `/a2a` JSON-RPC `message/send` and `tasks/get` adapter to the existing guest agent runtime. It is disabled unless all of `VIKTOR_TWIN_GRANT_FILE`, `VIKTOR_A2A_AUDIENCE`, `VIKTOR_A2A_TENANT`, and `VIKTOR_A2A_PUBLIC_KEY_FILE` are set. The public key is Ed25519 PEM, owned by root or the bot process, and not writable by group/others. The audience must be the exact HTTPS AgentCard URL; the tenant must match the live guest owner grant.

An authenticated request needs a signed EdDSA JWT (`iss=twin`, `sub=owner:tg:<positive numeric id>`, `aud=<exact AgentCard URL>`, integer `iat`, `exp<=iat+300`, `jti`) and the guest grant must bind the same `tg-<id>` principal to the configured workspace. The client must send `tvin.owner_scope={tenant,ownerId}` in message metadata. The adapter reserves `(workspace,principal,requestId)` durably and persists the task-text digest before running the real agent with read-only `read_learnings`. A duplicate request with different text fails 409. `tasks/get` reads only the matching owner-scoped durable reservation and receipt. A timeout leaves the task working or failed for reconciliation, never launches another model run. A completed Task artifact is agent text, **not** proof of delivery to the owner or accuracy of business claims.

The guest's legacy `/v1/agent/run` and existing bearer grant remain unchanged. Installing a verifier key, configuring HTTPS proxy/guest route, enabling the verified card, and a sanctioned owner-channel Task/readback are separate gates, not proven by these local tests. Never expose the bot gateway directly to the internet, invent a grant, or mark the card verified based on this candidate alone.
